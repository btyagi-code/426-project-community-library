Sprint 4 AI Usage Disclosure

For Sprint 4, I used AI as a support tool for a limited part of my implementation work. I did not ask AI to build the entire sprint or generate the complete project for me. I mainly used it to help with the observability setup, small code edits, formatting, and troubleshooting while I was implementing and integrating the sprint requirements.

I reviewed the suggestions before using them, made changes where needed, and tested the implementation myself.

1. Observability Module

One area where I used AI assistance was the observability.js module. I needed a consistent observability setup across the services so that each service could expose health and metrics information in a similar way. I asked AI for help understanding how to structure a reusable observability module and how to organize the common monitoring code.

Representative questions/prompts I asked

The exact wording may have varied, but my requests were along the lines of:

Help me create a reusable observability module for my Node/Express microservices.

I need the services to expose /health and /metrics endpoints. What is a clean way to organize that code?

How can I avoid repeating the same metrics setup directly inside every service's index.js file?

Can this observability logic be placed in a separate observability.js file and imported by each service?

Help me check whether this observability code is structured correctly for multiple services.

What I used from the AI assistance

I used AI suggestions to help structure the common observability logic and organize it into a reusable module.

After I had a working version, I copied/reused the same observability.js module across the services because the services required the same basic observability behavior. This is why the files are identical or very similar across the services.

The repeated file was not the result of separately generating six different files. I intentionally reused the same working module because the functionality was common across all of the services.

What I did myself

I integrated the module into the project, connected it to the individual services, ran the services, checked the health endpoints, verified that the services were starting correctly, and tested the overall Docker Compose environment.

2. gateway-service/index.js

I also used AI for a small amount of help while editing gateway-service/index.js.

The assistance was mainly related to code cleanup, formatting, and small refactoring suggestions rather than generating the gateway service itself.

Representative questions/prompts I asked

My requests were similar to:

Can you clean up this section of my gateway service without changing the behavior?

Can you make this code easier to read?

Is there a clearer way to format this array or block?

Help me refactor this small section while keeping the same logic.

Can you check this file for small syntax or formatting issues?

What I used from the AI assistance

Some of the AI suggestions changed code that had previously been written on one line into a multi-line format. For example, arrays such as BRANCHES or other short blocks may have been reformatted across multiple lines.

Those formatting differences are why some Sprint 4 edits look different from the style I used earlier in the project.

The underlying gateway implementation was not fully generated by AI. I used AI mainly for small edits and readability improvements.
